================================================================================
NOTES - ACP wire format summary (derived from this capture + acp_adapter/* source)
================================================================================

Transport: newline-delimited JSON-RPC 2.0 over the child's stdin/stdout.
            Hermes logs to stderr. Wire field names are camelCase.

GOTCHA (Windows native, Hermes 0.13.0): Hermes can leak a human-readable line to
STDOUT instead of stderr, e.g. when a `sudo` UAC prompt times out it prints
  `  (clock) Timeout - continuing without sudo`
straight to stdout. That is NOT valid JSON-RPC. hermes_client.py MUST skip
non-JSON stdout lines (log + continue), never crash on them. (Seen in the
sudo-whoami probe run, probe_output_perm.txt.)

Handshake:
  -> initialize {protocolVersion:1, clientCapabilities:{fs:{readTextFile,writeTextFile},terminal}, clientInfo:{name,version}}
  <- result {protocolVersion:1, agentInfo:{name:"hermes-agent",version:"0.13.0"},
             agentCapabilities:{loadSession:true, promptCapabilities:{image:true},
                                sessionCapabilities:{fork:{},list:{},resume:{}}},
             authMethods:[{id:"custom",name,description}]}
  -> session/new {cwd:"<forward-slash path>", mcpServers:[]}
  <- result {sessionId:"<uuid>",
             models:{availableModels:[{modelId:"custom:<name>",name,description}], currentModelId:"custom:<name>"}}
     (with the Ollama "custom" provider, availableModels = every pulled Ollama model.)

  Also advertised (not exercised in the probe):
    session/load   {cwd,sessionId,mcpServers} -> {models}   (replays history as session/update chunks)
    session/resume {cwd,sessionId,mcpServers} -> {models}
    session/fork   {cwd,sessionId,mcpServers} -> {sessionId}  (deep-copies history into a new session)
    session/list   {cursor?,cwd?} -> {sessions:[{sessionId,cwd,title,updatedAt}], nextCursor}
    session/cancel {sessionId} -> interrupts the running turn
    session/set_model {sessionId,modelId};  session/set_mode, session/set_config_option accepted as no-ops.

Prompt turn:
  -> session/prompt {sessionId, prompt:[{type:"text",text:"..."}]}   (also image / resource_link / embedded_resource blocks)
  ... stream of session/update notifications ...
  <- result {stopReason:"end_turn"|"cancelled"|"refusal",
             usage:{inputTokens,outputTokens,totalTokens,thoughtTokens,cachedReadTokens}}

session/update notifications - params = {sessionId:"<uuid>", update:{...}}:
  {sessionUpdate:"available_commands_update", availableCommands:[{name,description,input:{hint}?}]}
  {sessionUpdate:"usage_update", size:<ctx window>, used:<est tokens>}
  {sessionUpdate:"agent_thought_chunk",  content:{type:"text",text:"..."}}   <- reasoning delta
  {sessionUpdate:"agent_message_chunk",  content:{type:"text",text:"..."}}   <- assistant text delta
  {sessionUpdate:"user_message_chunk",   content:{type:"text",text:"..."}}   <- only during history replay / queued-prompt echo
  {sessionUpdate:"tool_call", toolCallId:"tc-<hex>", title, kind:"execute|read|edit|search|fetch|think|other",
       locations:[{path,line?}], content:[{type:"content",content:{type:"text",text:"..."}}]}   <- tool start
       (write_file/patch starts carry {type:"diff",path,oldText?,newText} blocks instead)
  {sessionUpdate:"tool_call_update", toolCallId:"tc-<hex>", kind, status:"completed",
       content:[{type:"content",content:{type:"text",text:"..."}}]}   <- tool result

  -> Loom event mapping:
       agent_thought_chunk -> {type:"thinking_delta", text}
       agent_message_chunk -> {type:"text_delta", text}
       tool_call           -> {type:"tool_start", tool_id=toolCallId, name=<from title/kind>, json=<content text>}
       tool_call_update    -> {type:"tool_result", tool_id=toolCallId, content=<content text>}
       usage_update/final usage -> {type:"usage", input_tokens, output_tokens}
       prompt result       -> {type:"result", session_id, stop_reason, duration_ms}

PERMISSION FRAME - agent -> client request (from acp_adapter/permissions.py; not
captured here - qwen3.6:27b only ran benign commands and Hermes handles `sudo`
via its own password flow, not ACP request_permission):
  <- {jsonrpc:"2.0", id:<n>, method:"session/request_permission", params:{
        sessionId:"<uuid>",
        toolCall:{ a ToolCallStart, e.g. {toolCallId:"perm-check", title:"<command>", kind:"execute"} },
        options:[ {optionId:"allow_once",  kind:"allow_once",  name:"Allow once"},
                  {optionId:"allow_always",kind:"allow_always",name:"Allow always"},
                  {optionId:"deny",        kind:"reject_once", name:"Deny"} ]}}
  -> client reply (JSON-RPC response, same id):
        allow:  {result:{outcome:{outcome:"selected",optionId:"allow_once"}}}   (allow_always -> allow_once for v1)
        deny:   {result:{outcome:{outcome:"selected",optionId:"deny"}}}
        n/a:    {result:{outcome:{outcome:"cancelled"}}}
  Hermes maps kinds -> internal: allow_once->"once", allow_always->"always", reject_*->"deny".
  Timeout (default 60s) or any error -> Hermes treats as "deny".
  -> Loom: emit {type:"permission_request", request_id=<n>, tool_name, tool_input}; route through the
     existing browser /api/cc-permission UI; reply on the same JSON-RPC id from an async task so the
     stdout read loop never blocks (v1 deadlock guard).

OTHER OBSERVED FACTS:
  - On session/new Hermes (via call_soon) pushes available_commands_update + usage_update around the
    session/new RESULT; the client must tolerate updates for a sessionId it just learned.
  - Closing the child's stdin mid-protocol -> `hermes acp` exits code 1 (acp lib raises, entry.py sys.exit(1)).
    Expected on cancel/teardown; don't treat exit!=0 there as a hard failure.
  - cwd: send a forward-slash path. Hermes runs the terminal tool via Git Bash (logs cwd as /c/Users/...),
    and falls back to a parent dir if the exact path "is missing on disk" (it warns).
  - config.yaml model.context_length:65536 is honored: stderr shows
    "Ollama num_ctx capped: 262144 -> 65536 (model.context_length override)".
