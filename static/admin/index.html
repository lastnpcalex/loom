Loom Conversation Modes

                    
Loom — Claude Code via the Anthropic API; the model dropdown also carries Codex and Antigravity groups, switchable mid-conversation. Braid — Claude Code on the local llama-server. Hermes — the ACP agent on the same local model. Weave — structured RP with characters, personas, and the OODA state harness. NROL-AO — the locked-down epistemic-engine operator: file and shell tools stripped, beliefs move only through typed, human-approved transitions.

                    
Everything shares one branching tree, one search index, one chat surface: highlight any message text to quote it in your next send; attach files; queue messages mid-generation; branch, fork, and regenerate without losing anything.

                


                

                    
NROL-AO — The Operator Loop

                    
Nothing moves a posterior except commit_match on a pending proposal, or submit_transition with an indicator_id and commit=true. Prose never moves beliefs — no matter how well it describes the evidence.

                    
In an NROL-AO conversation, these plain requests run the whole machine:

                    
    
                        
  1. "Run the evidence loop on <topic>" — status check, then a scan: web search per hypothesis, full-article fetch, strict matcher, and the advocate / rebuttal / jury debate over its PARKs. Safe policy: PARK and SCHEMA_GAP auto-apply (they cannot move posteriors); FIRE and OBSERVE land in the proposal queue.
    2. 
                        
  2. "Show me the pending proposals" — review each: indicator binding, value and units, and whether several proposals describe the same underlying event (one causal event = commit ONE; the engine decays and de-correlates repeats, but don't lean on it).
    3. 
                        
  3. "Commit #N, withdraw the rest" — each commit raises a browser approval prompt. That click is the authority gate. Posteriors move through pre-committed likelihoods, repeat-fire decay, and the confidence-inflation guard; the result reports before → after.
    4. 
                        
  4. "Work down the parked queue" — review_parked re-judges shelved evidence against the current schema with full article text and the debate. Items stay in the retained archive (kept-but-timestamped) but escalations return to step 2 as rebind proposals that commit against the existing ledger entry. The parkedReviewDebt.dueCount number in topic_status is the active work queue; flaggedForIndicatorReview is archive size.
    5. 
                        
  5. "Show shadow posteriors" — the dynamics model's first-passage probabilities, derived from pre-committed regime priors plus elapsed time (Gamma conjugacy prices "still closed, day N"). Zero authority; divergence from committed posteriors is a calibration conversation, not an error.
    6. 
                    

                


                

                    
NROL-AO — Creating a Topic

                    
Say: "Design a topic for <question> — hypotheses with priors and a written rationale, tier-1 indicators with pre-committed LRs, and a dynamics spec." The pipeline behind it:

                    
    
                        
  1. design_topic drafts through the governor gates — inadmissible hypotheses (unclear, unobservable, unfalsifiable) block creation outright; a priors_rationale is required and recorded as the topic's first history entry.
    2. 
                        
  2. The red-team review is mandatory and runs automatically: verdict SOUND or REVISE stamped on the draft. UNREVIEWED drafts can never activate; activating over a REVISE requires an explicit, logged override.
    3. 
                        
  3. activate_topic is the final human-gated commit — it also refuses any topic without a lint-clean dynamics spec, so every topic prices time-as-evidence from day one.
    4. 
                    

                    
Drafts move no beliefs and stay out of active listings until you approve activation in the browser.

                


                

                    
Reading the Digests (failure modes have names now)

                    

                        
Digest lineMeaning

                        
                            
no actionable evidence this window (a valid result)Real quiet window — articles were found and judged; nothing crossed a threshold.

                            
⚠ MATCHER FAILEDThe model returned no content (e.g. thinking budget exhausted). The scan window is left open so nothing is lost; investigate, don't interpret.

                            
⚠ DEBATE FAILEDA deliberation stage errored — zero rescues is a malfunction here, not consensus.

                            
deliberation: N parks debated, M argued, K rescuedThe jury layer working: K parked items escalated to proposals.

                            
parked: true, parked_reason: sustained observation…The engine declining to double-count an unchanged fact on an already-fired indicator. Correct behavior.

                            
scan coverage: … window left openlastScanned deliberately not stamped after a failure — the next scan re-covers these articles.

                        
                    

                


                

                    
Status & Known Gaps as of 2026-06-11

                    
Working, with acceptance tests: the full lifecycle (design → red team → activate → scan → deliberate → propose → human commit → posterior moves) and the parked-queue loop (re-adjudication → rebind commit). Pinned by test_FULL_LIFECYCLE… and test_THE_LOOP… in the NROL suite.

                    
Open items: dynamics evidence_nudges have no gated write tool yet (specs are repo-edited); the shadow model needs 2–3 weeks of comparison against committed posteriors before promotion to a typed transition; debate quality on live batches is unproven; the Hormuz parked backlog (~109 due) awaits a full review_parked sweep now that rebind commits land.
